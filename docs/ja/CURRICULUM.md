# カリキュラム – MUD School

> [🇸🇪 Svenska](../sv/CURRICULUM.md) · [🇬🇧 English](../en/CURRICULUM.md) · 🇯🇵 日本語

> MUD サーバーと対応するクライアントをゼロから作りながら **Go** と **Rust** を学ぶ。
> 20 行のエコーサーバーから、タイルグラフィック、スクリプト、再起動なしで読み込める
> プラグインを備えた拡張可能なゲーム世界まで。

この文書は旅の *全体* を説明します。なぜこの形なのか、各ステップで何を学ぶのか、
どこへ向かっているのか。レッスン 01〜13 は `lessons/` に実装済み（テストと模範解答
付き）です。フェーズ 3〜6 は計画中で、全体像が見えるように、そして自分で発展させ
られるようにここで説明しています。

## 教育の考え方

### 1. 消えていく演習ではなく、育っていくゲーム

コースを通して作るプログラムは **1 つ** です。レッスン 04 のコードはレッスン 13 でも
生きています。つまり、自分の決定と付き合い、世界が変わればリファクタリングする
必要があります。本物のプロジェクトと同じです。どのレッスンも、誰かに *動かして
見せられる* ものができて終わります。

### 2. 問題が必要としたときに概念を学ぶ（ジャストインタイム）

「本に載っているから」という理由で導入される言語の概念はありません。どの概念も
ゲームが必要としたときに登場します:

| 問題 | 概念 |
|---|---|
| 2 人目のプレイヤーが入れない | ゴルーチン（02） |
| 2 人が同時にログインするとサーバーが落ちる | `sync.Mutex`、データ競合（05） |
| 回線の悪い 1 人がサーバー全体を止める | チャネル、`select`、ソケットごとに書き手は 1 つ（07） |
| 入力中にクライアントがメッセージを取りこぼす | Rust のスレッドとチャネル（06） |
| あるクライアントではマップを緑に、別のでは画像にしたい | インターフェース、意味と見た目の分離（10） |
| サーバーが色々な種類のメッセージを送る | データ付き enum、`match`（11） |
| 600 部屋はコードでは書けない | JSON、検証、`go:embed`（09） |

だから、概念の書き方だけでなく、*なぜ* その概念があるのかがわかります。

### 3. 2 つの言語、意図を持って

**まず Go。** Go は小さく寛容な言語で、ネットワークプログラミングは得意分野です。
2 レッスンで動くマルチプレイヤーサーバーができます。この早い成功体験が、難しい
部分を乗り越える力になります。

**話し相手ができたら Rust。** Rust はサーバーがすでにあるレッスン 03 で登場します。
Rust は難しいですが、具体的な課題と、テスト相手（自分のサーバー）があるなかで学べます。

**対比による学習。** どの Rust レッスンにも *Go ↔ Rust* の比較があります。同じ考え
（チャネル、エラー、インターフェース）が 2 通りに表現されるのを見ると、1 つの言語
しか知らない場合よりも考えそのものを深く理解できます。*何を*（並行性、エラー処理）と
*どうやって*（ゴルーチンかスレッドか、`error` か `Result` か）を区別できるようになります。

**適材適所。** この分担は恣意的ではありません。何千もの同時接続を扱うネットワーク
サーバーには Go、グラフィックと細かな制御が必要なクライアントには Rust。フェーズ 5 では
2 つの言語が出会います。Rust で書いて WebAssembly にコンパイルしたプラグインが、
Go のサーバーの中で動くのです。

### 4. テストが仕様書

どのレッスンにも `./mudschool check` が実行するテストがあります。読みやすく書かれて
いて、失敗メッセージは何が期待され何が起きたかを、あなたの言語で伝えます。作業は
赤 → 緑 → リファクタリングの流れになります。`./mudschool watch` は保存のたびに
テストを実行するので、数秒でフィードバックが得られます。

サーバーのテストの多くは **TCP 越しのブラックボックステスト** です。本物のクライアント
と同じようにサーバーへ接続します。つまり、正しく振る舞う限り、コードの構成は自由です。

### 5. だんだん減っていく支援（スキャフォールディング → フェーディング）

| フェーズ | もらえるもの | 自分で書くもの |
|---|---|---|
| 1 | `TODO` 付きの骨組みと、ほぼ完成した関数シグネチャ | 関数の中身 |
| 2 | 型とシグネチャを含む新しいファイル、残りの説明 | 関数、既存コードの変更 |
| 3〜4 | 契約（プロトコル、インターフェース）とテスト | 設計と、コースのもの以外の自分のテスト |
| 5〜6 | 目標といくつかの指針 | テストも含めてすべて |

### 6. ちょうどよい量の手助け

- `./mudschool hint` はヒントを **1 つずつ** 出します。正しい方向へのひと押しから、
  ほぼコードのものまで。まず自分で試しましょう。
- `./mudschool solution` は模範解答を見せます。写すためではなく、*後で比べる* ために
  使いましょう（`diff -ru`）。
- **考えてみよう** – 各レッスンにある振り返りの問いです。答えてみてください（できれば
  書いて、または学習仲間に声に出して）。理解が定着するのはそこです。
- **チャレンジ** – もっとやりたい人向けの任意の発展課題です。テストには影響しません。

### 7. コースは 3 つの言語で

説明、ヒント、コースツール、テストの失敗メッセージ、ゲーム内のテキスト、ゲームの
世界は **スウェーデン語・英語・日本語** で用意しています（`./mudschool init --lang sv|en|ja`、
後で `./mudschool lang` で変更可能）。コードとコメントは英語です。実際の現場でコードに
出会うのはその形ですし、すべての受講者が互いの解答を読めます。プレイヤー向けの
テキストを専用ファイル（`messages.go`）にまとめることは、ゲーム自体の
*国際化* への第一歩でもあります。

### 8. 変化をつけた繰り返し

中心となる考えは、だんだん難しい形で戻ってきます。Go のチャネル（07）→ Rust の
チャネル（06、13）→ ゲームループのアクターパターン（フェーズ 3）→ `tokio::select!`
（フェーズ 6）。エラー処理: `error`（01）→ 自作のエラー（05）→ `errors.Join`（09）→
`Result` と `?`（03）→ 自作のエラー型（11）。同じ考えに再会するたびに、少しずつ
深く理解できます。

## 各レッスンの進め方

```
./mudschool show        # 1. 読む: 目標、概念、課題
                        # 2. workspace/ にコードを書く
./mudschool watch       # 3. 保存するたびにテストが走る
./mudschool hint        # 4. 行き詰まった？ ヒントを 1 つずつ
./mudschool run server  # 5. 実際に動かす（telnet、自分のクライアント）
                        # 6. 「考えてみよう」に答え、チャレンジに挑む
                        # 7. 模範解答と比べる
```

どの README も同じ構成です: **目標 → 小さな例付きの概念 → 課題 → 自分で試す →
考えてみよう → チャレンジ**。

## フェーズ 1 – 基礎（レッスン 01〜05）

**目標:** telnet でログインできるマルチプレイヤーサーバーと、Rust の最初の
クライアント。両方の言語で簡単なプログラムを読み書きできるようになる。

| # | トラック | レッスン | ゲームに加わるもの | 言語で学ぶこと |
|---|---|---|---|---|
| 01 | Go | こんにちは、TCP！ | エコーサーバー | パッケージ、関数、メソッド、構造体、`error`、`defer`、`net`、`bufio` |
| 02 | Go | 大勢で同時に遊ぶ | 複数の同時プレイヤー | ゴルーチン、クロージャ、`sync.WaitGroup`、レース検出器 |
| 03 | Rust | こんにちは、Rust！ | 自分のクライアント | Cargo、モジュール、`struct`/`impl`、`Result`/`?`、`Option`、所有権と借用、`String`/`&str` |
| 04 | Go | コマンド | `look`、`help`、省略形、コマンド登録表 | `strings`、マップ、スライス、値としての関数、テーブル駆動テスト |
| 05 | Go | プレイヤー | ログイン、重複しない名前、`who` | 自作のエラー、`errors.Is`、`%w`、ルーンと UTF-8、`sync.Mutex` |

## フェーズ 2 – 世界と顔（レッスン 06〜13）

**目標:** 探検できる世界、グラフィッククライアント向けのプロトコル、そして端末で
動くカラーマップ・ステータスバー・ログ付きのクライアント。

| # | トラック | レッスン | ゲームに加わるもの | 言語で学ぶこと |
|---|---|---|---|---|
| 06 | Rust | スレッドとチャネル | 受信と入力を同時にできるクライアント | `thread::spawn`、`move`、`mpsc`、ジェネリクス、トレイト境界、`Send`/`'static` |
| 07 | Go | チャット | `say`、ログイン・ログアウトの通知、遅いクライアント対策 | チャネル、バッファ付きチャネル、`select`/`default`、バックプレッシャー |
| 08 | Go | 部屋 | 部屋、出口、`look`、移動、`shout` | ポインタ、可変長引数、ファクトリとしてのクロージャ、ロックの約束事 |
| 09 | Go | 世界ファイル | JSON の 21 部屋、検証、`-world` フラグ | `encoding/json`、構造体タグ、`io.Reader`、`errors.Join`、`go:embed` |
| 10 | Go | プロトコルとマップ | JSON プロトコル、マップ、ステータス。telnet もそのまま動く | インターフェースとエンコード、`sync/atomic`、2 次元グリッド |
| 11 | Rust | Rust でプロトコル | JSON を理解するクライアント | データ付き enum、`match`、`let-else`、serde、`Display` |
| 12 | Rust | カラーのマップ | Dwarf Fortress 風の色付きタイル | `Copy`、イテレータ、`fmt::Write`、ANSI コード |
| 13 | Rust | 本格的な画面 | TUI: ステータスバー、ログ、マップ、入力欄 | ratatui、`From`/`Into`、イベント enum、`TestBackend` |

**フェーズ 2 を終えると**、小さいながら本物の MUD ができています。ひと息つくのに
よいタイミングです。誰かに見せたり、気に入らない部分を書き直したり、チャレンジに
挑んだりしましょう。

## フェーズ 3 – 生きている世界（計画中）

**目標:** 誰も何も入力していなくても世界が動いている。アイテム、生き物、戦闘、
そして再起動しても残るプレイヤー。

| # | トラック | レッスン | 内容 |
|---|---|---|---|
| 14 | Go | ゲームループ | `time.Ticker` が世界を動かす（例: 毎秒 10 ティック）。ミューテックスから **アクターパターン** へリファクタリング: *1 つ* のゴルーチンが世界全体を所有し、チャネルでコマンドを受け取る。きれいな終了のための `context.Context`。2 つのモデルを比較する。 |
| 15 | Go | アイテムと持ち物 | `get`、`drop`、`inventory`、`examine`。インターフェース（`Describer`）、構造体の埋め込み、ジェネリックな補助関数（`func Find[T Named](items []T, name string) T`）。 |
| 16 | Go | 生き物 | 歩き回り、話し、反応する NPC。状態機械、`Behavior` インターフェース、テストしやすいようシードを固定した `math/rand/v2`。 |
| 17 | Rust | 豊かなログ | プロトコルにテキストの種類（`"kind":"say"`、`"combat"`、`"system"`）を追加する後方互換の拡張。色付きのログ、コマンド履歴、スクロール。`HashMap<Kind, Style>`、`VecDeque`。 |
| 18 | Go | 戦闘 | 能力値、ダイスロール、ティックごとの戦闘ラウンド、死と復活。乱数を注入した決定的なテスト。 |
| 19 | Rust | クライアントでの戦闘 | HP メーター、ターゲットパネル、命中時の点滅。`event::poll(timeout)` と `Instant` による時間制御の描画。 |
| 20 | Go | 保存 | プレイヤーとアイテムを SQLite に保存（`database/sql` + `modernc.org/sqlite`、純粋な Go）。bcrypt によるパスワード。マイグレーション。 |
| 21 | Rust | 設定とログイン | ログイン画面、設定ファイル（`serde` + `toml`）、`clap` によるコマンドライン引数、`thiserror` による自作エラー型。 |
| 22 | 両方 | 本格的なテスト | `ParseCommand` のファジング（`go test -fuzz`）、Rust のプロパティベーステスト（`proptest`）、CI でサーバー相手に遊ぶボットクライアント。 |

## フェーズ 4 – タイルとゾーン（計画中）

**目標:** 部屋のグラフから *Caves of Qud* 風のタイルの世界へ。各部屋は **ゾーン** に
なります。例えば 80×25 マスのマップで、1 マスずつ歩きます。端を越えると次のゾーンへ。
レッスン 10 の部屋マップは *ワールドマップ* になります。クライアントは本物の
グラフィックを手に入れます。

| # | トラック | レッスン | 内容 |
|---|---|---|---|
| 23 | Go | ゾーン | タイルと `(x, y)` を持つエンティティのあるゾーン。プロトコルに `zone` フレーム（ゾーン全体）と `delta` フレーム（変更点のみ）を追加。毎ティックすべてを送らない理由を学ぶ。 |
| 24 | Go | 手続き生成 | セルオートマトンによる洞窟、「酔歩（drunkard's walk）」によるトンネル、ノイズ（simplex）による地形。同じ世界を再現できるよう、すべてシードから生成する。 |
| 25 | Rust | カメラ | 大きなゾーンの一部を表示し、プレイヤーを追い、スクロールする。座標系、`saturating_sub`、`clamp`。 |
| 26 | Go | 視界 | サーバー側での再帰的 *シャドウキャスティング*（不正ができないように）と「戦場の霧」: 一度見たが今は見えないマスを暗く描く。 |
| 27 | Go | 経路探索 | `container/heap` とジェネリクスを使った生き物の A*。（*Brogue* のような）ダイクストラマップと比較する。 |
| 28 | Rust | グラフィッククライアント | `macroquad`（簡単）または `bevy`（大きなエコシステム）で専用ウィンドウ。CP437 タイルセット（16×16 の文字。Dwarf Fortress のタイルセットと同じ考え）か、Kenney の *1-Bit Pack* のような CC0 素材を読み込む。**2 つの実装を持つトレイト `Renderer`** – 端末とタイル – を作れば、クライアントの残りは変わらない。レッスン 10 の判断が報われるところです。 |
| 29 | Rust | 光と命 | 色が混ざる光源、アニメーションする水、パーティクル、命中時の画面の揺れ。*Brogue* 風のライティング。 |
| 30 | Rust | マウス | クリックで歩く（クライアントで A*）、マウスを乗せると「古いトウヒ」とツールチップ表示、右クリックメニュー。 |

このとき、クライアント全体は **Cargo ワークスペース** として整理します: `mud-core`
（プロトコル、状態）、`mud-tui`、`mud-gfx`。モジュール設計のよい練習です。

## フェーズ 5 – 拡張可能なサーバー（計画中）

**目標:** 新しい内容や機能のためにサーバーを再起動する必要をなくす。コースの集大成で、
すべてがつながります。

| # | トラック | レッスン | 内容 |
|---|---|---|---|
| 31 | Go | データの再読み込み | 世界ファイルを監視し（ポーリングか `fsnotify`）、検証して（レッスン 09！）、ゲームループの中で世界を *アトミックに* 入れ替える。消された部屋にいたプレイヤーは安全な場所へ移す。管理コマンド `@reload`。 |
| 32 | Go | Lua のスクリプト | `gopher-lua`（純粋な Go）で Lua を組み込む。`.lua` ファイルに書いたコマンドや NPC の振る舞いを稼働中に再読み込み。サンドボックス（`os`/`io` なし）、`context` によるスクリプトごとの時間制限、そして難問: *スクリプトにどんな API を与えるべきか？* レッスン 04 のコマンド登録表が急に重要になります。 |
| 33 | Rust → Go | WebAssembly のプラグイン | **Rust** でプラグインを書き、`wasm32-unknown-unknown` にコンパイルし、Go サーバーの中で `wazero`（純粋な Go、cgo なし）で動かす。独自の ABI: プラグインは `on_command(ptr, len)` を公開し、サーバーは `send(player, text)` を提供する。メモリ制限、無限ループ対策の「燃料」、バージョン管理。**ここで 2 つの言語が本当に出会います。** |
| 34 | Go | イベントとフック | イベントバス: `OnEnterRoom`、`OnSay`、`OnTick`、`OnDeath`。スクリプトとプラグインが購読し、フックは行動を取り消せる（「扉には鍵がかかっている」）。 |
| 35 | Go | Copyover | 90 年代からある MUD の古典的な技法: サーバーが `exec` で *新しいバージョンの自分* を起動し、開いている接続（`ExtraFiles` によるファイルディスクリプタ）とプレイヤーの状態を引き渡す。プレイヤーに見えるのは「世界が一瞬震えた……」だけ。誰も切断されずに新しいコードへ。 |
| 36 | Go | ゲーム内での建築 | *オンラインクリエーション*: `@dig north 暗い洞窟`、`@desc ...`、`@exit ...` – 変更は検証され、世界ファイルに保存され、すぐに全員に見える。 |

拡張性の 3 段階（簡単なものから強力なものへ）:

```
 データ（JSON、稼働中の再読み込み） →  スクリプト（Lua） →  プラグイン（WASM） →  新しいバイナリ（copyover）
     内容                               振る舞い             高速で隔離された        それ以外すべて
                                                             任意の言語のコード
```

## フェーズ 6 – 外の世界へ（選択コース）

一番興味のあるものを選んでください:

- **Web クライアント:** Go の WebSocket ゲートウェイと、Rust から WebAssembly に
  コンパイルしたクライアント。同じ `render` のコードがブラウザの `<canvas>` に描きます。
- **非同期 Rust:** `tokio` でクライアントを書き直す。`tokio::select!` は Go の `select` と
  驚くほど似ています。1000 人のボットプレイヤーで負荷試験ツールを作る。
- **本物の telnet:** IAC ネゴシエーション、NAWS（ウィンドウサイズ）、**GMCP**。Mudlet の
  ような一般的な MUD クライアントでも、あなたのマップとステータスバーを表示できるように。
- **運用:** `log/slog`、`pprof`、Prometheus 向けのメトリクス、Docker、TLS、スパムや
  過負荷への対策。
- **本格的な国際化:** プレイヤーごとに言語を選び、サーバーがプレイヤーごとにテキストを
  選ぶ（`text/template` によるメッセージカタログ）。
- **サーバー側の Rust:** 視界や生成のコードを Rust のライブラリとして書き、性能と
  開発体験を比べる。
