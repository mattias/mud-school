# プロトコル – mudschool 1

> [🇬🇧 English](../en/PROTOCOL.md) · [🇸🇪 Svenska](../sv/PROTOCOL.md) · 🇯🇵 日本語

これはサーバー（Go）とクライアント（Rust）の間の契約です。レッスン 10（サーバー）と
レッスン 11（クライアント）で導入します。

## 基本ルール

- 通信: TCP。テキストはすべて **UTF-8**。
- メッセージは両方向とも、`\r\n`（CR LF）で終わる **1 行** です。
- クライアントは常に普通のテキストを送ります: `look` や `say hello` などのコマンド。
- サーバーは、クライアントがあいさつを送るまでは **普通のテキスト** を送ります。
  その後は **1 行に 1 つの JSON フレーム** を送ります。

こうすることで `telnet` や `nc` はこれまでどおり動き、プロトコルを理解するクライアントは
構造化されたデータを受け取れます。

## ハンドシェイク

クライアントはいつでも（ふつうは接続直後に）次を送ります:

```
@hello mudschool 1
```

サーバーは `hello` フレームで応答し、以後は JSON を送ります:

```json
{"type":"hello","text":"mudschool 1"}
```

`@hello` で始まる行がゲームのコマンドとして解釈されることはありません。

## フレーム

フレームはどれも、フィールド `type` を持つ JSON オブジェクトです。

### `text`

```json
{"type":"text","text":"マドビー広場\n石畳の広場。中央に古い井戸がある。"}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `text` | 文字列 | 表示するテキスト。`\n` を含むことがある。空なら省略される。 |
| `kind` | 文字列 | テキストの種類。クライアントが色付けできるように（サーバーはレッスン 15 から送り、クライアントはレッスン 17 から使う）: `info`、`room`、`say`、`move`、`error`、`combat`。省略 = `info`。**未知の種類は `info` と同じように表示すること**（新しい種類が増えることがある）。 |

```json
{"type":"text","text":"ベルティル:「やあ！」","kind":"say"}
```

テキストはサーバーの言語です（`messages.go` を参照）。

### `map`

すべての `look` の後（つまり移動やログインの後にも）、またコマンド `map` への応答として
送られます。

```json
{"type":"map","map":{
  "width":5,"height":5,
  "rows":["  +  ","  |  ","  @-+","     ","\"    "],
  "legend":{"+":"inside","|":"path_ns","@":"self","-":"path_ew","\"":"field"}
}}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `width`、`height` | 整数 | マップの大きさ（文字数）。 |
| `rows` | 文字列のリスト | `width` 文字の行が `height` 行。各文字は **コード**。空白 = 何もない。 |
| `legend` | オブジェクト | `rows` で使われるコード → 意味。 |

部屋は偶数番目の行と列にあり、その間に出口が描かれます。プレイヤーは常に中央にいます。

バージョン 1 の意味:

| 意味 | コード | 説明 |
|---|---|---|
| `town` | `#` | 通り、広場 |
| `inside` | `+` | 屋内 |
| `road` | `.` | 道 |
| `field` | `"` | 草原、野原 |
| `forest` | `T` | 森 |
| `water` | `~` | 水 |
| `mountain` | `^` | 山 |
| `cave` | `o` | 洞窟 |
| `stairs_up` | `<` | 上への出口がある部屋 |
| `stairs_down` | `>` | 下への出口がある部屋 |
| `path_ew` | `-` | 東西の出口 |
| `path_ns` | `\|` | 南北の出口 |
| `self` | `@` | あなた |

> **重要:** クライアントはコードではなく **意味**（`legend`）にもとづいて描画してください。
> コードは telnet で読みやすいように選んでいますが、変わることがあります。

### `status`

すべての `look` の後と、戦闘の各ラウンドの後に送られます。

```json
{"type":"status","status":{"name":"Anna","room":"マドビー広場","terrain":"town","hp":10,"max_hp":10,"online":2}}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | 文字列 | プレイヤーの名前 |
| `room` | 文字列 | 部屋の名前 |
| `terrain` | 文字列 | 部屋の地形（上の意味のいずれか） |
| `hp`、`max_hp` | 整数 | 体力 |
| `online` | 整数 | ログイン中のプレイヤー数 |
| `target` | オブジェクト | 戦っている相手（レッスン 18 から）: `{"name":"ネズミ","hp":3,"max_hp":5}`。省略 = 誰とも戦っていない。 |

### `prompt`

サーバーが特別な入力を待っています（レッスン 20 から）。質問そのものは、その直前に通常の
`text` フレームとして届きます。

```json
{"type":"prompt","prompt":"password"}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `prompt` | 文字列 | `password`（既存のアカウント）または `new_password`（パスワードを決める）。クライアントは入力を **隠し**、履歴に保存しないこと。他の値が来ることもあるので、その場合は通常の入力として扱う。 |

telnet に `prompt` フレームが届くことはありません。

## 互換性

古いクライアントを壊さずにプロトコルを拡張できなければなりません:

1. **クライアントは未知の `type` のフレームを無視すること**（Rust では `#[serde(other)] Unknown`）。
2. **クライアントは未知のフィールドを無視すること。** フィールドは追加されるだけで、変更はされません。
3. **クライアントは任意のフィールド（例: `text`）がなくても動くこと。**
4. 正しい JSON でない行は普通のテキストとして表示する。
5. 互換性のない変更には新しいバージョンが必要: `@hello mudschool 2`。
