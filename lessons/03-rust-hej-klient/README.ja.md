## なぜ 2 つの言語？

| | Go（サーバー） | Rust（クライアント） |
|---|---|---|
| 強み | シンプルで書きやすく、ネットワークと並行処理に最適 | 細かく制御でき、GC の停止がなく、コンパイラが早期にバグを見つける |
| メモリ | ガベージコレクタ（GC） | 所有権と借用 – コンパイル時に検査 |
| エラー | 普通の戻り値としての `error` | `Result<T, E>` と `?` |
| 値がない | `nil` | `Option<T>` – `Some(x)` か `None` |

Go のエラー処理はもう見ました。Rust も似ていますが、コンパイラがエラー処理を
**強制** します。

## 5 分でわかる Rust

```rust
pub struct Point { x: i32, y: i32 }        // 構造体

impl Point {                               // メソッドは impl ブロックに書く
    pub fn new(x: i32, y: i32) -> Point {  // 「関連関数」（コンストラクタのようなもの）
        Point { x, y }
    }
    pub fn len2(&self) -> i32 {            // &self = 点を借りる（読み取り）
        self.x * self.x + self.y * self.y  // ; のない最後の式が戻り値
    }
    pub fn move_right(&mut self) {         // &mut self = 変更のために借りる
        self.x += 1;
    }
}

fn parse_port(s: &str) -> Result<u16, std::num::ParseIntError> {
    let port: u16 = s.parse()?;            // ? = Err ならすぐにエラーを返す
    Ok(port)
}
```

**Go ↔ Rust:** Go の `x, err := f(); if err != nil { return err }` は
Rust では `let x = f()?;` に相当します。

### 所有権を一言で

どの値にもちょうど 1 人の所有者がいます。値は *貸し出す* ことができ、
多数の読み手（`&T`）か、ただ 1 人の書き手（`&mut T`）のどちらかです。
両方同時はありません。

### `String` と `&str`

`String` は所有された伸長可能なテキストバッファ、`&str` は借りたテキストの
一部です。関数は普通、引数に `&str` を取り（どちらも渡せる）、`String` を返します。

## 課題

コースツールが `workspace/client/src/net.rs` を作ってくれています。

1. `src/lib.rs` に `pub mod net;` を追加し、モジュールをライブラリの一部に
   します（Rust はファイルを自動では見つけません。モジュールを宣言する
   必要があります）。
2. `net.rs` の 3 つのメソッドを実装する（`todo!()` を置き換える）。
3. `src/main.rs` を書き、クライアントが次のことをするようにする:
   - 1 番目の引数のアドレス、なければ `127.0.0.1:4000` に接続する、
   - あいさつの行を表示する、
   - ループでキーボードから 1 行読み、送信し、返事を表示する。

テスト（`tests/mudschool_03.rs`）は偽のサーバーを起動して `Connection` だけを
テストしますが、`main.rs` も書きましょう。でないと動かすクライアントがありません！

> クライアント自身のテキスト（「接続先:」など）は `src/messages.rs` にコースの
> 言語で入っています: `println!("{} {addr}", messages::CONNECTED_TO);`
