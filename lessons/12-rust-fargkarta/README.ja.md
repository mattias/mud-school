# レッスン 12 – カラーのマップ

ここから見た目が良くなります。Dwarf Fortress、Caves of Qud、NetHack、Brogue は
*1 マスに 1 文字* で世界全体を表しますが、文字と色をうまく選ぶと驚くほど雰囲気が
出ます。私たちも同じことをします。マップのコードを色付きの **タイル** にします。

```
    Ω─Ω
    │ │
    ▲ Ω
    │
≈─"─·─♣─♣
      │ │
      · ♣
```

♣ 緑の森、≈ 青い水（濃い青の背景付き）、▲ 灰色の山、# 石造りの家、· 道、@ あなた（黄色）。

これはフェーズ 4 の本物のタイルグラフィックへの第一歩でもあります。そこでは
`Cell { glyph: '♣', ... }` を「スプライトシートの 5 番目のタイル」に置き換えますが、
残りのコードは同じままです。

## 目標

- 移動ではなくコピーされる小さな **Copy 型**（`Rgb`、`Cell`）を作る。
- 文字列に対して、予備の腕 `_` 付きで `match` を使う。
- **イテレータ** を使う: `iter`、`chars`、`map`、`collect`、`enumerate`。
- 端末が **ANSI エスケープコード** で色を描く仕組みを理解する。

## Rust の概念

### Copy

```rust
#[derive(Clone, Copy, PartialEq)]
pub struct Rgb(pub u8, pub u8, pub u8);   // 「タプル構造体」: 名前のないフィールド

let a = Rgb(255, 0, 0);
let b = a;          // コピー – a はまだ使える（Copy のおかげ）
let Rgb(r, g, b) = a;   // 分解
```

`Copy` がなければ、`let b = a;` は値を *移動* していました。数値だけからなる小さな
値は `Copy` にぴったりです。`String` や `Vec` は決して `Copy` にはなれません。

### イテレータ

```rust
let grid: Vec<Vec<Cell>> = map.rows
    .iter()                                  // 各行の &String
    .map(|row| row.chars().map(to_cell).collect())  // 行ごとの Vec<Cell>
    .collect();                              // Vec<Vec<Cell>>
```

イテレータは *遅延評価* です。`collect`（または `for` ループ）が値を引き出すまで
何も起きません。コンパイラはこの連鎖を手書きのループと同じくらい速いコードにします。

**Go ↔ Rust:** Go ではほぼいつも `for` ループを書きます。Rust ではどちらのスタイルも
よく使われます。一番わかりやすいほうを選びましょう。

### ANSI コード

端末は特定の文字の並びを命令として解釈します:

| コード | 意味 |
|---|---|
| `\x1b[38;2;R;G;Bm` | 前景色（トゥルーカラー） |
| `\x1b[48;2;R;G;Bm` | 背景色 |
| `\x1b[0m` | リセット |

試してみましょう: `printf '\x1b[38;2;40;170;70m♣\x1b[0m\n'`

どの端末ライブラリ（crossterm、ratatui、ncurses）も内部でこれを行っています。
一度自分でやってみましょう。次のレッスンではライブラリに任せます。

## 課題

1. **`src/render.rs`**（新しいファイル）: `tile`、`render_map`、`to_ansi` を書く。
   `lib.rs` に `pub mod render;` を追加する。
   - `tile` は意味ごとに固有の文字と合った色を返す（テストは例えば、森が緑で
     水が青かを確認します）。未知の意味にはわかりやすい予備のセル（例えばマゼンタの
     `?`）を返す。
   - `render_map`: 空白は `BLANK`、凡例にあるコードは `tile(意味)`、凡例に *ない*
     コードはそのままの文字を灰色で表示する。
   - `to_ansi` はファイルのコメントのとおり。
2. **`src/main.rs`**: `to_ansi(&render_map(&map))` でマップを描く。

## 自分で試す

サーバーとクライアントを起動して歩き回りましょう: `s`、`s`、`s`、`s`、`e` ……

> 変な文字が見えますか？ 端末は UTF-8 で、その文字を含むフォントを使う必要が
> あります。色が出ませんか？ 端末がトゥルーカラーに対応していないのかもしれません
> （最近のものはたいてい対応しています）。`docs/ja/SETUP.md` を参照してください。

> **日本語の端末について:** `≈ ▲ ■ ─ │` などの記号は、端末の設定によって全角
> （2 マス幅）で表示されることがあり、マップがずれます。その場合は端末の
> 「East Asian Ambiguous Width」の設定を「半角（1）」にしてください。

## チャレンジ

- 森に変化をつける: 位置（`enumerate` で x と y がわかる）に応じて `♣`、`♠`、`↑` を
  使い分け、森を生き生きと見せる。ローグライクでよく使われる工夫です。
- *ローグライクの色彩理論* を調べる: 遠くのものほど暗い色にする、色数を絞った
  パレット（例えば「PICO-8」のパレット）を使う。
