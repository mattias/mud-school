# レッスン 24 – 手続き生成

世界には部屋が 21 あり、どのゾーンも壁に囲まれた長方形です。21 のゾーンを手で描くのは
退屈で、600 なら不可能です。*Caves of Qud*、*Brogue*、*Dwarf Fortress* のようなゲームは、
小さなアルゴリズムでマップを生成します。しかも **シード** から生成するので、同じ世界を
正確に再現できます。

```
###############.###############     TTTTTTTTTTTTTTT.TTTTTTTTTTTTTTT
###############.###############     T"""""""""TT""""""""""""""TTTTT
#########....##..#....#####.###     T"""""""""""T"""""""""""""TTTTT
########......##.......##....##     T"""""""""T"""""""""""""""TTTTT
###..##......................##     .""""""""TTTT"TTT""""""""TTTTTT
##...........................##     T""""""T""TTTTTTTTT"""""TTTTTTT
###.........###>.......###..###     T"""""""""TTTTT""""""""""TTTTTT
     洞窟（セル・オートマトン）                 森（ノイズ）
```

## 目標

- 3 つの古典的なアルゴリズムを実装する: **セル・オートマトン**、**バリューノイズ**、
  **酔歩**（drunkard's walk）。
- シード付きの乱数生成器を使い、すべてを再現でき、テストできるようにする。
- 生成したものの性質（*どの出口からも別の出口へ歩いて行ける*）を塗りつぶし
  （flood fill）で保証する。

## Go の概念とアルゴリズム

### シード

```go
rng := rand.New(rand.NewPCG(seed, hashString(r.ID)))
```

部屋ごとに、世界のシード *と* 部屋の ID（`hash/fnv` でハッシュ化）で決まる独自の乱数列を
使います。シードを変えれば世界全体が変わり、そのままなら世界はどのコンピューターでも同じです。

### セル・オートマトン（洞窟）

ゾーンをノイズ（45% が壁）で埋め、単純なルールを何度か適用します: *周囲 9 マス（自分を
含む）のうち 5 マス以上が壁なら壁になる*。孤立した壁は消え、孤立した穴はふさがり、
残ったものが洞窟のように見えます。

```
前:         1 ステップ後:
#####       #####
#.#.#       ##.##
#...#   ->  ##.##
#.#.#       ##.##
#####       #####
```

### バリューノイズ（森、野原、湖）

マスごとの乱数は砂嵐のように見えます。**ノイズ** は *なめらかに* 変化する乱数です。
粗い格子（*lattice*）の上の乱数値を、その間でなめらかにつなぎます。近い点は近い値に
なるので、木は林になり、湖には岸ができます。

```go
// a, b, c, d: (x, y) の周りの格子の値、tx, ty: smooth(小数部分)
top := a + (b-a)*tx
bottom := c + (d-c)*tx
return top + (bottom-top)*ty
```

*フラクタル* ノイズは複数の層（オクターブ）を足し合わせます。大きな形と細かな模様。
そしてしきい値でタイルを決めます: `n > 0.5` → 木。

### 酔歩（トンネル）

生成したマップには困った癖があります。たどり着けない隅や、岩に埋もれた出口。解決法:
一番大きな開けた領域を見つけ（flood fill）、そこに含まれない出口からはふらふらした
トンネルを掘ります。歩みの 70% は目標へ、30% はどこへでも。それでも到達できないマスは
埋めるので、閉じた空間に誰かが置かれることはありません。

## 契約

- `GenerateZone(r *Room, w, h int, seed uint64) *Zone` – 地形ごとに: `cave`（壁/床）と
  `mountain`（岩/床）はセル・オートマトン、`forest`、`field`、`water` はノイズ、`town`、
  `inside`、`road` は単純な床。その後、地形の縁のタイルで枠を描き、出口の開口部
  （`openExits`）、そして `connectZone`。
- 同じ部屋とシード → まったく同じゾーン。シードや部屋が違えば別のゾーン。
- 生成されたゾーンでは、**歩けるすべてのマス** にどの開口部からも到達でき、端は開口部
  以外は閉じている。
- `caStep(grid [][]bool) [][]bool` – 4-5 ルール（グリッドの外のマスは壁として数える）。
- `ValueNoise(seed, x, y)` – `[0,1)` の範囲、同じ入力なら同じ値、なめらか。
- `reachable(z, start) map[Pos]bool` – 塗りつぶし。
- `drunkardWalk(z, from, to, rng, floor)` – `from` と `to` をつなぎ、端には決して触れない。
- ワールドファイルに `"seed": 42` が加わる。手作りのゾーンがない部屋は、世界のシードと
  ゾーンの大きさで `GenerateZone` を使う。

## 課題

`gen.go` は `caStep`、`ValueNoise`、`FractalNoise`、`reachable`、`drunkardWalk`、
`connectZone` 以外は用意されています。その後 `World` と `worldFile` に `Seed` を加え、
`makeZone` から `GenerateZone` を呼ぶようにします。

歩き回ってみましょう: `./mudschool run server`、`./mudschool connect`、`go west` を何度か、
`zone`。別のシードを書いた自分のワールドファイルで `-world` も試してみましょう。

  ないとしたらなぜ？

## チャレンジ

- `inside` と `town` に部屋と廊下（BSP）: ゾーンを何度も二分割し、それぞれに部屋を置いて
  つなぐ。
- バリューノイズの代わりに本物の **シンプレックス** ノイズやパーリンのグラディエント
  ノイズ。見た目を比べてみる。
- 世界の地域ごとに違うシードを使い、町はそのままで「鉱山」だけを毎日作り直す。
