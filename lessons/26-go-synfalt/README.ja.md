# レッスン 26 – 視界

これまでは全プレイヤーにゾーン全体を送ってきました。壁の向こう、角の先、隣の部屋まで。
ゲームでは、これはずるの温床です。改造したクライアントなら何でも見えてしまいます。
そこでサーバーが、各プレイヤーに **見える** ものを決め、それだけを送ります。

```
#####################      o  あなた
#*******************#      *  見える
#*******************#      .  見えない（柱の影）
#*******************#
#*******************#
#*********o*#.......#  <- 柱（#）は見えるが、その向こうは見えない
#*******************#
```

知識には 2 種類あります:

- **見える（visible）** – *今* 見えているもの（1 歩ごとに変わる）。
- **探索済み（explored）** – *いつか* 見たもの。そのタイルはマップに残るので、来た部屋を
  覚えていられます。「戦場の霧」です。

## 目標

- ローグライクの古典的アルゴリズム **再帰的シャドウキャスティング** を実装する。
- 再帰、浮動小数点の傾き、対称性（1 つのオクタントを 8 回）を使う。
- サーバーが *知っている* ことと、クライアントが *知ってよい* ことを分ける。

## アルゴリズム

視界を 8 つのオクタント（三角形）に分けます。それぞれで、外へ向かって 1 行ずつ走査します。
まだ照らされている行の部分の *傾き* `start` と `end` を覚えておきます（最初は 1.0 から
0.0）。走査が壁にぶつかったら:

1. その向こうの行について、壁の左端までの部分だけ再帰する。
2. 壁の後は新しい `start`（壁の右端）で続ける。

行がふさがったまま終わったら、そのオクタントは終わりです。その向こうはすべて影です。

```go
for j := row; j <= radius; j++ {
	dy := -j
	for dx := -j; dx <= 0; dx++ {
		left := (float64(dx) - 0.5) / (float64(dy) + 0.5)
		right := (float64(dx) + 0.5) / (float64(dy) - 0.5)
		// start..end の外は飛ばし、マスを見えるとし、壁を扱う
	}
}
```

8 つのオクタントは、座標を反転・交換した同じコードです。オクタント内の `(dx, dy)` は
`(dx*xx + dy*xy, dx*yx + dy*yy)` になります。表 `octants` は用意されています。

## 契約

- `ComputeFOV(z *Zone, origin Pos, radius int) map[Pos]bool` – 原点は見える。原点からの線が
  届く `radius` 以内（ユークリッド距離: `dx²+dy² <= radius²`）のマス。壁、木、岩は見えるが、
  その向こうをさえぎる（`Transparent`、レッスン 23）。水はさえぎらない。
- `PlayerSight = 8`。
- `updateFOV(p)` – `p.fov` を保存し、`p.explored[部屋ID]` に加え、新しく見たマスを
  読む順（1 行ずつ、左から右）に返す。
- **zone フレーム:** `rows` には探索済みのタイルだけ（残りは `' '`）、凡例には出てくる
  コードだけ、`visible` は視界を `'1'` と `'0'` の行で表したもの。`entities` は見えるもの
  だけ、そして自分自身は常に。telnet にも同じ行が見える。
- **delta フレーム** に `tiles`（初めて見たタイルの `[{x, y, code, meaning}]`）と、視界が
  変わったときの `visible`（全行）が加わる。見えなくなったエンティティは `removed`、見える
  ようになったものは `added`。*何か* 変われば、`visible` だけでも delta を送る。
- 探索済みの部分は、ログインしている間は部屋ごとに覚えておく。

## 課題

1. `fov.go`: `castLight` と `updateFOV`（`ComputeFOV`、`octants`、`visibleRows` は用意済み）。
2. `Player`: `fov`、`explored`、`seenVisible`。
3. `sync.go`: `ZoneData.Visible`、`TileChange`、`DeltaData.Tiles`、`DeltaData.Visible`。
   `zoneData` が探索済みのタイルと `visibleEntities` だけを見せるようにし、`syncPlayer` が
   新しいタイルと変わった `visible` を加えるようにする。

レッスン 25 の Rust クライアントは新しいフィールドを無視します（serde は未知のフィールドを
無視する）。新しく見えたタイルを表示するのはレッスン 28 からです。

## 考えてみよう

- なぜ視界はクライアントではなくサーバーで計算しなければならないのでしょう？
- `ComputeFOV` はコマンドとティックのたびに全プレイヤーについて走ります。31×13 なら
  どれくらいのコスト？ 200×200 で 100 人なら？ 何をキャッシュできる？
- シャドウキャスティングは *対称* でしょうか？ A から B が見えるなら、B から A も見える？
  いくつか試してみよう。遠距離攻撃のあるゲームではなぜ大事？
- 生き物にはまだ視界がありません。レッスン 27 で必要になります。

## チャレンジ

- 光: 松明を持っていなければ視界が 3 になる暗い洞窟。
- 扉（`+`）が閉じているときは視界をさえぎるようにする。
- `explored` をデータベースに保存し、訪問の間もマップを覚えておく。
