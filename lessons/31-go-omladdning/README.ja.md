# レッスン 31 – 世界の再読み込み

フェーズ 5 の始まりです。目標は **サーバーを決して再起動しなくてよい** こと。新しい中身や
機能を加えるときも、プレイヤーは接続したまま、周りの世界が変わっていきます。最も簡単な
ものから最も強力なものまで、4 つの段階があります:

```
 データ（JSON、その場で再読み込み） ->  スクリプト（Lua） ->  プラグイン（WASM） ->  新しいバイナリ（copyover）
   レッスン 31、36                        レッスン 32、34       レッスン 33           レッスン 35
```

このレッスンが最初の段階です。`world.json` を編集し（誤字を直す、部屋を足す）、保存すると、
1 秒後に世界が揺らめき、全員が新しい世界に立っています。

## 目標

- ライブラリなしでファイルを監視する: `os.Stat` と `time.Ticker` による **ポーリング**。
- 遅い処理（ファイルの読み込みと検証）はゲームループの **外**、入れ替えはループの **中** で。
  不可分に行うので、誰も半分の世界を見ることはない。
- 生きている状態を古い構造から新しい構造へ移す（プレイヤー、位置、アイテム）。
- 簡単な権限チェックでコマンドを守る: **管理者**。

## Go の概念

### ポーリング

```go
t := time.NewTicker(s.reloadEvery)
defer t.Stop()
for {
	select {
	case <-s.stop:
		return
	case <-t.C:
		fi, err := os.Stat(path)  // ModTime か Size が変わった？
	}
}
```

`fsnotify` のようなライブラリは、問い合わせる代わりに OS から知らせてもらいます。でも 1 つの
ファイルなら、1〜2 秒ごとのポーリングは簡単で移植しやすく、十分に安上がりです。`s.stop` の
`select` に注目: ゴルーチンはサーバーとともに終わり、リークしません。

### まず検証、後で入れ替え

```go
nw, err := LoadWorldFile(path)   // ループの外: ディスク + 検証（レッスン 9）
s.do(func() {                    // ループの中: すばやい入れ替え
	if err != nil { /* 管理者に伝え、古い世界を残す */ return }
	s.swapWorld(nw)
})
```

ファイルが壊れていれば *何も* 変わりません。管理者にはレッスン 9 のエラーメッセージが届き、
ファイルを直せます。

### 状態の移行

新しい世界には新しい `*Room`、`*Item`、`*NPC` の値があります。古い世界を指していたものは、
すべて新しい世界を指さなければなりません:

- プレイヤー: 同じ ID の部屋（なくなっていれば開始部屋）、まだ歩ける位置。
- 持ち物: 同じ ID の新しい世界のアイテム（その部屋から取り出す）。
- 戦闘: 打ち切る。生き物が新しくなったので。
- ゾーン: `seenRoom` と `explored` を忘れ、クライアントに新しい zone フレームが届くように。

### `@` 付きのコマンド

管理者のコマンドは `@` で始まります。ラッパーが権限を確かめるので、コマンド自身は確かめなくて
済みます:

```go
func adminOnly(fn CommandFunc) CommandFunc {
	return func(s *Server, p *Player, cmd Command) {
		if !s.isAdmin(p) { p.SendKind(KindError, MsgNotAdmin); return }
		fn(s, p, cmd)
	}
}
```

関数を受け取って関数を返す関数。レッスン 8 の `moveCommand` と同じ考え方です。

## 契約

- `Options.WorldPath`（ワールドファイル、`""` = なし）、`Options.ReloadEvery`（0 = 監視しない）、
  `Options.Admins`（名前。プレイヤー名と同じように正規化する）。
- ファイルが変わったら（ModTime か Size）、ゲームループの外で読み込んで検証する:
  - 正しければ世界を入れ替える。全プレイヤーに `MsgReloaded` と `look`。部屋がなくなった
    プレイヤーには `MsgRoomGone` を送り、開始部屋へ。持ち物は同じ ID の新しい世界のアイテムに
    置き換える（そのアイテムはもう部屋には落ちていない）。戦闘は止まる。
  - 誤りがあれば何も変えない。ログイン中の管理者に、エラー付きの `MsgReloadFailed`。
- `@reload`（管理者のみ。それ以外は `MsgNotAdmin`。ワールドファイルがなければ
  `MsgNoWorldFile`）は同じことをすぐに行う。
- `main.go`: `-reload 2s` と `-admin Anna,Bertil`。

## 課題

`reload.go` は一部用意されています（`isAdmin`、`adminOnly`、`notifyAdmins`、`cmdReload`、
`normalizeAdmins`）。`reloadFromFile`、`watchWorld`、`swapWorld` を書きましょう。次に
オプション、`Server` のフィールド、`start` での監視の開始、コマンド、フラグ。

試してみましょう: 世界をコピーし（`cp server/mud/world.json my-world.json`）、
`-world my-world.json -admin 自分の名前` でサーバーを起動し、ログインして、ファイルの説明を
変えてみます。

## 考えてみよう

- なぜ入れ替えはゲームループの中で、読み込みは外で行わなければならないのでしょう？
- 新しいゾーンでは壁になったマスにプレイヤーが立っていたら？ どうなるべき？
- ポーリングの最中にファイルが保存されたら（書きかけ）？（テストは一時ファイルに書いてから
  名前を変えます。なぜそれで助かる？）
- 立て続けの 2 回の再読み込みが、逆の順で適用されることはある？
- 管理者は *名前* にすぎません。データベースなし（`-db ""`）や、アンナが登録する前なら、
  誰でもアンナとしてログインできます。しかもレッスン 35–36 は管理者に `@copyover` と
  ワールドファイルを書く権利を与えます。パスワードあり（レッスン 20）で動かし、管理者の名前を
  先に登録しましょう。ほかに何が欲しい？

## チャレンジ

- `items.json` と `npcs.json` を別々に再読み込みし、何かをしている最中の生き物が続けられる
  ようにする。
- `@reload` で差分を見せる: 加わった部屋、消えた部屋、変わった部屋。
- ポーリングの代わりに `fsnotify` を使って比べてみる。
